# OP-004 交接：PostgreSQL/pgvector 与核心领域模型

## 结果

- 新增根目录 `compose.yml`，`core` profile 目前只包含固定镜像 `pgvector/pgvector:0.8.6-pg17-bookworm` 的 OpsPilot PostgreSQL；监听 `127.0.0.1:55432`，具有健康检查和项目专属持久卷，不包含最终应用镜像、Redis、MinIO、Superset 或 Docker Socket。
- 新增 `src/opspilot/db/`：SQLAlchemy 2.x declarative base、持久化 enum、11 个领域模型和显式 Engine/Session 工厂。导入模型和 FastAPI 启动均不会连接数据库。
- 新增 Alembic `0001_create_core_domain_schema`：启用 vector 扩展并创建 Organization/TargetSystem、KnowledgeDocument/Version、RetrievalIndexVersion/KnowledgeChunk、ToolDefinition/ProviderBinding/CatalogSnapshot、ToolExecution/AuditEvent。
- 父子块用复合外键绑定同组织、目标、文档版本和检索版本；触发器拒绝 child→child、表示混版和非数值 Sparse 权重。父块无向量，READY 子块必须同时具有 1024 维 Dense 与 Sparse 表示。
- 工具定义仅含 OpsPilot 稳定名；Provider 上游名只存在于 binding/执行快照。执行触发器校验稳定名、Schema、Provider 类型、binding 版本、上游名及目录快照均与同范围版本记录一致；MCP 或带目录哈希的 binding 缺少匹配快照时直接拒绝，外部目录观察不会自动产生授权。
- DocumentVersion、CatalogSnapshot、ToolExecution 与 AuditEvent 都是 append-only；检索版本仅允许固定 lifecycle 转换，ToolDefinition/ProviderBinding 的语义字段不可原地修改。变更必须新建版本或追加事件。
- 未创建用户、工单、诊断运行、Evidence、Action/Approval/Verification、Agent/Skill/Delegation/Evaluation 表；未实现知识入库/RAG、Tool Gateway、Provider 调用、Agent、HITL、Specialist 或业务 API。
