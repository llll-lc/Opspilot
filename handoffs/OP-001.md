## 3. 可复现基准

### 本地 BGE

条件：Windows CPU、PyTorch 4 线程、推理并发 1、短批次 4、7 次计时。

| 模式 | 加载 | P50 / P95 | 输出 | RSS 峰值 |
|---|---:|---:|---|---:|
| BGE-M3（组合样本） | 9.30 s | 424 / 607 ms | 1024 维，首向量 L2=1.0 | 组合峰值内 |
| BGE-Reranker-Large（组合样本） | 12.29 s | 835 / 920 ms | 4 个 raw logits | 组合峰值内 |
| 同进程组合 | 21.59 s 总加载 | 同上 | 两模型均真实推理 | 5,193,195,520 bytes（约 4.84 GiB） |

模型文件：BGE-M3 2,297,543,916 bytes（权重 2,271,145,830）；reranker 2,244,804,285 bytes（权重 2,239,705,845）。本地 JSON 结果在被忽略的 `spikes/op001/results/*.local.json`。

失败复盘：

1. 首次资源不足时标准加载无 Python 异常退出，不能据此判定文件损坏。
2. 释放内存后仍得到 `0xC0000005`；分层验证确认模型结构和 391 个权重键可读取/注入，崩溃在 `sentencepiece==0.2.2`。
3. `tokenizers==0.22.2` 可读取 BGE-M3 `tokenizer.json`（250,002 词）；两个模型 SentencePiece 文件哈希同为 `CFC8146A...0DB2865`，故 reranker 安全复用 fast JSON。
4. reranker 旧检查点只忽略非参数缓冲键 `roberta.embeddings.position_ids`；其他不匹配仍失败。

容量结论：组合能跑，但不与 `target-reports` 默认同时常驻；日常 embedding 单实例，reranker 小候选集按需，最终保留取决于 OP-005 收益评测。

## 4. 定版结论

- Agent/API：FastAPI + 一张开源 LangGraph 主图 + PostgreSQL checkpointer/store。
- 核心数据：独立 OpsPilot PostgreSQL + pgvector；Superset 元数据库独立容器/卷。
- Agent 侧 Redis：删除。MinIO：首版删除。Reranker：可选/按需。
- profiles：`core`、`ingest-eval`、`target-light`、`target-reports`、`observability`。
- 最终包装：一个 OpsPilot 应用镜像/容器，其他有状态/目标服务由一个 Compose 入口分容器编排。
- 测试控制面：out-of-band、项目作用域、默认关闭；Agent 无 Docker Socket、Shell、任意 SQL 或 Superset 元库写权限。
