## 范围

1. 增加仅含 OpsPilot PostgreSQL/pgvector 的开发基础设施，固定 `pgvector/pgvector:0.8.6-pg17-bookworm`，提供项目隔离命名、健康检查、持久卷和非敏感本地默认值；不构建应用镜像。
2. 建立 SQLAlchemy 2.x 数据库组合根、命名约定和显式连接入口；导入模型不连接数据库，FastAPI 进程健康入口仍不探测外部依赖。
3. 建立 Alembic 配置与首个可升降迁移，启用 `vector` 扩展，并创建以下最小模型：
   - `Organization`、`TargetSystem`；
   - `KnowledgeDocument`、不可静默覆盖的 `KnowledgeDocumentVersion`；
   - `RetrievalIndexVersion`、结构化 `KnowledgeChunk` 父子块及 Dense/Sparse 表示；
   - `ToolDefinition`、`ToolProviderBinding`、`ProviderCatalogSnapshot`；
   - `ToolExecution`、`AuditEvent`。
4. 用数据库约束、外键、唯一索引和触发器保护组织/目标系统隔离、父子块同文档同检索版本关系、仅子块参与表示、`vector(1024)` 维度、检索表示版本一致性、稳定工具与实际 Provider 历史快照。
5. 提供单元测试和 PostgreSQL 实际环境验证，覆盖 upgrade/downgrade/upgrade、pgvector 版本与维度、无 ANN 索引、父子块合法/非法写入、组织隔离、版本不可混用，以及 Provider 绑定/目录/执行/审计链。
6. 回写 `docs/03_DOMAIN_AND_DATA_MODEL.md` 的实际表/迁移落点，并更新任务状态、当前状态和交接。

## 实现与安全约束

- 所有业务数据保留 `organization_id`；目标相关模型同时绑定 `target_system_id`，数据库层拒绝跨组织父子或 Provider 审计关联。
- 知识更新创建新文档版本和新检索版本，历史 Chunk、工具 Schema、Provider 目录与执行快照不可因后续配置变化而失去解释性。
- 父块只提供上下文且不保存 Dense/Sparse 表示；子块必须引用合法父块。READY 子块必须具有 `vector(1024)`、Sparse 权重和与索引版本一致的表示版本。
- Dense 只建立精确查询所需类型，不创建 HNSW/IVFFlat；Sparse 只保存经 Schema 约束的词项权重，不在本任务实现评分。
- ToolDefinition 只保存 OpsPilot 稳定名；绑定和执行记录明确区分 `MCP`、`REST`、`PROBE`、`INTERNAL`，并保存上游名、目录哈希、范围摘要、降级原因、关联 ID 和安全摘要。模型中不预授权任何具体工具。
- 普通配置、日志、测试夹具和提交不得包含真实密钥、Cookie、连接串或完整敏感响应。
