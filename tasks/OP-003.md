# OP-003：Superset 最小目标系统、原生 MCP 风险闸门与故障真值

状态快照（非权威，以 `TASKS.md` 为准）：`DONE`

## 范围

- 为 Superset 6.1.0 的轻量、报表和 MCP 实验 profile 补充可重复的本地编排、种子、只读验证与隔离的测试控制面；不构建最终交付镜像。
- 实测并保存机器可读 MCP 风险闸门证据：启动方式、端点/传输、工具目录及哈希、认证与 RBAC 边界、上游工具禁用、审计、响应大小、超时、资源、断连/认证失败的降级方向。
- 固化 MCP 只读允许名单及拒绝规则的测试证据；若固定镜像不能安全满足要求，明确标记为未通过，保留 REST/只读 Probe 回退方向，不宣称已接入。
- 明确并测试 CONNECTOR（MCP）、APPLICATION（Superset Web/API）、RUNTIME（Worker/Beat/Redis）和 BUSINESS_JOB（调度任务）四种健康语义及不可互相替代的结论。
- 定义版本化、机器可读 `FaultScenario` 真值和场景生命周期控制；完成连接、权限、调度三个家族共五个最小场景（调度含两个不同根因），每个场景连续三次 `reset → inject → assert active → recover → assert clean`，并至少经过真实 Superset API/健康或日志链路。
- 保存可重跑的验证脚本、非敏感 JSON 报告和场景/运行证据；合成用户、日志、描述必须显式标识。

- 任意 SQL、Shell、Docker Socket 工具暴露给应用/模型，或直接写 Superset 元数据库；不得伪造 MCP 成功或业务返回。

## 实现与安全约束

- 以 ADR-003 和 `docs/02` 的稳定工具/Provider 边界为后续方向，但本任务不得提前实现 Tool Gateway 或 Provider 运行时。实验客户端与控制面不得被 Agent 包导入或注册。
- MCP 原始工具仅可验证 `health_check`、`get_instance_info`、`get_schema` 及数据库/数据集/图表/仪表盘 list/get 元数据；SQL、创建、保存、生成、更新和未知工具必须在原生配置与验证策略中拒绝。
- MCP 返回、工具描述、日志和场景话术均为不可信数据；报告不得记录 token、Cookie、密码、连接串或 `.env` 内容。
- 故障控制面只在测试 profile/网络中出现，普通开发 profile 默认不可访问；无 Docker Socket 挂载给 OpsPilot 服务。
- `health_check` 的成功只能形成 CONNECTOR 证据；Web/API、Worker、Beat、Redis 和调度结果分别形成 APPLICATION、RUNTIME、BUSINESS_JOB 证据。
- 故障真值在用户描述或日志变体之前定义；注入/重置断言失败为环境失败，不能计入业务正确性。重置必须只作用于命名明确的项目测试资源。
- 固定镜像或 MCP 风险闸门不通过时，文档状态必须为“未通过/待 OP-006 回退实现”，不能声称 MCP 已实现。

## 验收条件

1. `tasks/OP-003.md`、场景 Schema、五个场景清单、控制脚本和报告均可在不读取密钥的条件下定位；场景真值含根因、健康范围、必需观测、禁止操作、注入/恢复断言和合成标记。
2. 固定 6.1.0 的实际环境报告记录启动尝试、工具目录/哈希、认证/RBAC、禁用/拒绝、审计、响应/超时、资源、健康范围与降级结果；每项有 PASS、FAIL 或 NOT_APPLICABLE 的原因和命令证据。
3. MCP 不可用、认证失败、目录含不允许工具或响应/超时超限时，验证脚本安全失败并输出明确的 REST/只读 Probe 后续回退，而不把连接器状态冒充为目标系统健康。
4. CONNECTOR/APPLICATION/RUNTIME/BUSINESS_JOB 健康范围由自动化测试和报告分别断言；至少一个“连接器健康、运行时异常”的反例被验证。
5. 五个 Gate A 场景连续三次通过完整生命周期，无残留；至少一个真实 Superset REST API、一个真实健康/运行时或日志链路被机器验证。资源受限无法稳定的真实环节必须明确记录为受控 fixture 与原因。
6. 测试控制面不在普通 profile 暴露，且检查不含 Docker Socket、任意 SQL/写 MCP 工具或密钥泄漏。
7. 后端 `uv --cache-dir .cache/uv lock --check`、`ruff check .`、`ruff format --check .`、`mypy src`、`uv --cache-dir .cache/uv run pytest` 通过；前端 `pnpm --dir frontend format:check`、`lint`、`typecheck`、`build` 通过；`git diff --check` 通过。

## 完成证据

- 当前 MCP 证据为 `evidence/OP-003_MCP_GATE_2026-09-05.json`：JWT 认证为 `PASS`，24 个原生工具中发现 10 个危险工具，原生只读闸门为 `FAIL`；审计已观测。受控超限测试将隔离 profile 的响应上限降为 1 token，报告确认容器环境也为 1，仅调用只读 `get_instance_info`，却得到未拒绝的 416 B 成功响应，故原生响应大小执行为明确的 `FAIL`。带 `--require-size-rejection` 的验证器先保存报告，再以退出码 1 安全失败；极短客户端超时验证为明确的 `PASS`。这些均不是 `PARTIAL_ONLY`，并要求 OP-006 采用稳定工具允许列表与 REST/只读 Probe 回退。
- 当前 API 场景证据为 `evidence/OP-003_API_FIXTURE_LIFECYCLE_2026-09-05.json`：`F-AUTH-01` 创建并命名目标资源 `OP003 Restricted` 后，Gamma Reader 在三轮中对其 `GET /api/v1/database/{id}` 均得到 `404`，数据库列表均为 `200` 但过滤该名称；验证后删除测试资源（`created_fixture: true`、`removed: true`）。
- `evidence/OP-003_SCHEDULED_FAULT_LIFECYCLE_2026-09-04.json`：三个调度场景连续三次通过生命周期。`2026-09-04` MCP/API 报告保留为历史证据，已由上述当前报告取代。
