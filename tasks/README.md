# tasks 目录说明

`TASKS.md` 是任务编号、正式状态、依赖和主要交付的唯一权威来源。本目录只保存即将执行或正在执行任务的详细范围与验收规格。

当前只详细定义 `OP-001.md`。OP-002 及后续任务文件应在前置任务完成后依据实际版本、代码、资源和交接，用 `TASK_TEMPLATE.md` 创建。提前写死全部实现细节会让新会话重复或照着过期假设开发。

任务文件若包含“状态快照”，它只用于阅读便利，不得覆盖 `TASKS.md`。

创建后续任务文件时必须：

1. 读取前置任务交接、真实代码、测试和 Git。
2. 从专题规格引用边界，不复制整篇规格。
3. 写清本任务不做什么，尤其防止提前实现后续页面或抽象。
4. 使用可通过测试、断言、命令或文件检查验证的验收条件。
5. 将用户参与压缩到密钥、账号、下载批准、外部发布和主观验收。

不得删除已完成任务文件。历史规格与实际实现不同，记录真实结果和原因，不回写历史制造“从未改变”的假象。
