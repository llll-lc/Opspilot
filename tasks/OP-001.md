# OP-001：环境、资源与关键兼容性风险闸门

状态快照（非权威，以 `TASKS.md` 为准）：`DONE`

## 目标

在不开发正式业务功能的前提下，验证本机能否支撑 OpsPilot 的核心链路，消除版本、资源、Superset、Agent 服务、DeepSeek、本地模型和前端基线中的高风险假设，并形成明确回退结论。

开始环境操作前，必须做一次“规格—官方事实—本机现实”冲突审计。若冲突会改变核心部署形态，先更新规格或新增 ADR；不得表面沿用规划、实际私下实现另一套架构。

## 前置检查

- 检查 `git status`、最近提交和现有文件，确认未重复开始 OP-001。
- 检查端口、磁盘和当前 Docker 容器，不停止或删除用户其他项目资源。
- 检查是否已有同版本 Superset 源码/镜像/卷，避免重复下载。
- 所有外部下载先记录来源、许可证、预估大小和用途。

## 范围

### 1. 本机与开发工具

- 记录 Windows、WSL2、Docker Desktop/Engine/Compose、Git、Python、Node、包管理器和 PyCharm 可用解释器状态。
- 记录 CPU、物理/可用内存、D 盘空间、Docker 分配和关键端口占用。
- 不修改用户全局 Git、Python、Node、Docker 或 PyCharm 设置；确需修改先说明影响。

### 2. 本地模型基准

- 验证 `D:\Agent\models\bge-m3` 和 `D:\Agent\models\bge-reranker-large` 完整性。
- 建立最小可删除基准：加载时间、输出维度/分数、短批次 P50/P95、进程峰值内存。
- 分别测试单独加载和同进程/按需组合，默认推理并发 1。
- 只形成部署结论，不开发正式检索服务。

### 3. DeepSeek 兼容性

- 创建 `.env.example`，由用户只在本地 `.env` 填写 Key。
- 从执行时官方文档核对 Base URL、可用模型、工具/JSON能力和错误规则。
- 最小验证普通对话、结构化 JSON、工具调用、超时/无效 Key/限流类错误映射。
- 模型名、超时、重试和 Base URL 全部配置化。

### 4. Superset 可行性 spike

- 固定一个适合实验的 Superset tag/commit，记录官方仓库、Apache-2.0、NOTICE 和非官方声明。
- 验证 Docker Desktop/WSL2 下的最小 Web/API 启动，不宣称生产部署。
- 获取目标版本实际 OpenAPI 或确认公开 API：认证、用户/角色、数据库连接测试、数据集/仪表盘、报告计划（若版本支持）。
- 创建最小临时种子资源，验证至少一个公开 API 查询和一个只读健康/日志观测。
- 评估 `target-light` 与 `target-reports`：后者逐项加入 Target Redis、Worker、单一 Beat；浏览器/邮件只在必要时测试。
- 记录每个 profile 的内存、冷启动、磁盘、端口和失败原因。
- 验证 Agent 不挂 Docker Socket、不写 Superset 元数据库；设计 test-only control plane 隔离方案，只形成结论/最小 spike。

### 5. Agent 服务与数据候选

- 核对 Agent Server 当前自托管、许可、PostgreSQL/Redis、SDK、自定义 FastAPI 路由和资源要求。
- 用决策表比较 Agent Server 与 FastAPI + LangGraph 开源 persistence；选定候选或执行 ADR 回退。
- 验证 PostgreSQL + pgvector 镜像支持 `vector(1024)`，不创建完整业务表。
- 判断 Agent 侧 Redis、MinIO 是否有明确职责；没有则从定版技术栈移除。

### 6. 前端基线

- 对照 `D:\Agent\learning_knowledge` 中教程使用的前端与当前官方 Agent Chat UI。
- 比较许可证、上游活跃度、Next.js/React/Node、LangGraph SDK、中文化、线程、工具事件、文件附件和 interrupt 展示。
- 锁定确切上游 URL 与 commit/tag，只形成基线选择，不开发业务页面。

### 7. 输出

- 环境与版本清单。
- 规格冲突审计与处理结果。
- 资源基准表和可同时运行的 profile 组合。
- Superset/DeepSeek/BGE/pgvector/前端/Agent 服务兼容性结论。
- 选定技术、删除候选、回退路径和未解决风险。
- 必要的 ADR、版本文档、`handoffs/OP-001.md`、`CURRENT_STATE.md` 和 `TASKS.md` 更新。

## 不在范围

- 不实现正式工单、知识入库、Agent 图、工具网关、故障数据集或业务 UI。
- 不提前完成 OP-002/OP-003。
- 不把本地模型复制进仓库/镜像。
- 不引入多 Agent、MCP、Milvus、Elasticsearch、RAGFlow、Kubernetes。
- 不为 Agent 增加 Celery。
- 不把 Docker Socket、Shell、任意 SQL、Superset 元库写权限交给 Agent。
- 不清理用户已有 Docker 镜像、卷、容器、虚拟环境或下载缓存。

## 资源判断标准

- 单用户基准期间无 OOM、容器异常重启或持续严重换页。
- 模型不得因 Web worker 数量产生副本；推理并发默认 1。
- 若完整组合不可接受，先拆 profile、按需加载 Reranker、减少服务，再考虑替换技术。
- Superset 重型功能若无法同时常驻，可以分步骤演示；必须保留至少一个真实公开 API/状态链路。
- 记录事实和失败，不为漂亮结果隐藏 Windows/CPU 限制。

## 验收条件

- 规格冲突审计完成；发现的重要冲突已用最小改动修订或 ADR 记录。
- 所有运行时、IDE、Docker/WSL、端口、磁盘和资源信息有可复现记录。
- DeepSeek 普通、JSON、工具调用各有成功证据或明确阻塞；Key 未进入 Git/日志。
- 两个本地模型的输出、加载、延迟和峰值内存有可复现基准。
- PostgreSQL/pgvector 最小 `vector(1024)` 验证有证据。
- Superset 固定版本、许可证、最小启动、公开 API/健康观测和资源数据有明确结果。
- `target-light` / `target-reports` 可行组合或正式回退有证据。
- Agent Server/纯 FastAPI 路径和前端基线有确切选择及理由。
- Agent 侧 Redis/MinIO/Reranker 的“保留、可选或删除”结论清晰。
- 创建实际交接、更新权威状态并生成本地 Git 提交；不自动 push。

## 需要用户参与

- 批准必要依赖、Docker 镜像和官方源码下载。
- 若必须修改 Docker Desktop/WSL2 资源或网络设置，确认影响后由用户决定。
- 对候选前端的视觉/交互偏好做最终主观确认（若两个基线技术上都可行）。
