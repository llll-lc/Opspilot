## 范围

1. 新增机器可读知识来源 manifest 和最小合规语料：官方条目保留 URL、访问日期、目标版本、许可/再分发边界、内容哈希；合成 Runbook 明确标为项目合成资料且只保存短小自编内容，不复制大段第三方正文。
2. 在现有 `KnowledgeDocumentVersion`、`RetrievalIndexVersion`、`KnowledgeChunk` 契约上实现版本冻结入库：结构感知父子切块保留标题路径、结构类型、原文定位、内容哈希、来源/可见性/目标/版本等检索范围元数据；创建冻结索引版本后写入，不混用表示版本。
3. 实现 BGE-M3 的 1024 维 Dense 和 Sparse 表示生成、持久化及按需单例加载。沿用 OP-001 已验证的 Windows fast-tokenizer JSON 与非 mmap legacy `.bin` 回退；CPU 推理串行。
4. 实现始终先做强制元数据过滤的检索服务：精确错误码/配置键/任务名、pgvector 精确 Dense、Sparse、RRF 去重融合、可关闭且按需的 BGE-Reranker-Large、父块上下文扩展和可定位引用。
5. 冻结知识与查询真值，执行四组只改变 RAG 变量的独立消融：Dense-only、加精确、加 Sparse+RRF、加 Reranker；保存逐例结果与 Recall@K、MRR/nDCG、父块上下文命中、引用有效率、延迟、内存、失败查询及版本/环境元数据。
6. 建立固定 Registry 的首批三个版本化 Skill：`database-connectivity-triage`、`access-control-triage`、`scheduled-report-triage`。每个 Skill 含版本、内容哈希、触发/适用条件、必需观测、稳定工具名和建议顺序、证据门槛、停止/升级、禁止动作及结构化输出契约；实现解析、哈希校验、禁用/篡改/错误匹配拒绝和回归测试。
7. 更新任务、状态、交接和运行说明，并留下实际 PostgreSQL/pgvector 入库与检索、迁移、测试、静态检查、前端门禁、构建、锁文件、差异/密钥/大文件检查的证据。

## 实现与安全约束

- 以 ADR-003 的 L0/L2 单向边界为准：RAG 返回可追溯事实，Skill 仅约束排障方法；Skill 内容和知识正文均是不可信数据，不能授予工具或动作权限。
- 所有检索路径和消融组保持组织、可见性、目标系统、索引版本、来源类型及目标版本过滤；不得使用模型生成的范围标识。小规模只能使用 pgvector 精确检索。
- `KnowledgeDocumentVersion`、`RetrievalIndexVersion` 与已有表示完整性/不可变约束不得绕过或原地改写；父块不保存表示，子块表示必须与索引版本一致。
- 模型目录配置化，模型文件、缓存、原始第三方正文、数据库卷和大评测产物不得提交；CPU 并发固定为一，Reranker 默认关闭且按需释放。
- 技能只引用 OpsPilot 稳定工具名，当前不注册或调用它们；禁止动态下载、用户上传、任意 Shell/SQL、写操作或在 SKILL 中复制知识正文。
- 真值、语料、索引、配置和评测结果须版本/哈希可追溯；失败不删除、不以同一生成模型充当真值或裁判。

## 验收条件

1. `knowledge/` 的 manifest、合成 Runbook、冻结查询真值及来源/许可/哈希检查可定位；官方材料仅以链接和受限短摘要使用，合成内容均明确标识。
2. 单元测试证明结构单元不被硬切、标题/定位/哈希/范围元数据保留、冻结版本和表示版本不混用；实际 PostgreSQL 测试证明父子块、1024 Dense、Sparse 与范围过滤入库及可检索。
3. BGE-M3 实测生成 1024 维 Dense 与非空 Sparse，并沿用 Windows 回退；CPU 请求串行，模型按需加载。无模型条件下的确定性测试不依赖本机模型文件。
4. 检索测试分别覆盖精确、Dense、Sparse、RRF 去重、Reranker on/off、父上下文扩展、可定位引用、所有强制过滤和跨范围拒绝；无 HNSW/IVFFlat/ColBERT。
5. 四组使用同一冻结索引、查询集和过滤条件，各自产出逐例 JSON 与汇总指标，明确样本数、失败查询、资源/延迟和每项能力是否证明净收益，不夸大结论。
6. 三个固定 Skill 均通过正确解析与哈希验证；禁用、文件篡改、错误触发和越权/未知工具名均被拒绝，结构化输出契约和每类正/负/停止样本受回归测试保护。
7. `uv --cache-dir .cache/uv lock --check`、Ruff、format、`mypy src tests`、pytest、实际 PostgreSQL 迁移/入库/检索验证及 `alembic check` 通过；前端 frozen install、format、lint、typecheck、production build 通过；`git diff --check`、密钥和大文件检查无异常。
