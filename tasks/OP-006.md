## 范围

1. 新增身份、角色、目标资源范围和服务端 `AuthorizationContext` 的最小领域模型/API 依赖；所有组织、目标系统和资源范围由认证上下文注入，调用者提供的越权组织/目标/资源标识必须拒绝或忽略，不能交给模型决定。
2. 新增 `SupportCase`、消息/时间线所需的最小持久化模型与迁移，实施确定性状态机、版本并发保护、去重/幂等创建、角色驱动的转换以及 append-only 审计。实现仅限受理、诊断、等待用户、升级与安全关闭前置条件；不实现 Agent、审批、动作执行、验证或 UI。
3. 固定首批稳定只读工具契约和受限参数/结果 Schema：连接器健康、应用健康、运行时健康、实例摘要，以及数据库/数据集/图表/仪表盘授权范围内的 list/get 元数据。仅稳定名可被调用；禁止 SQL、任意 URL、任意上游工具、创建/保存/修改/删除和 Shell。
4. 实现 Tool Gateway：基于服务器注入范围和已审核的 `ToolDefinition`/Binding 选择 Provider，验证请求/返回、授权和资源对象，限制并脱敏结果，写入每次尝试的 `ToolExecution` 和关联 `AuditEvent`。Provider、上游工具名、目录哈希和降级理由只能作为审计快照，不得暴露为 Agent/Skill 契约。
5. 实现窄 REST/Adapter 与只读 Probe Provider；以可注入的受控客户端/fixture 覆盖元数据、应用健康和分组件运行时健康。保证 MCP connector、APPLICATION、RUNTIME_COMPONENT 的 evidence/结果 scope 不可混淆。
6. 实现受控 MCP Provider 边界：只接受固定原始 allowlist 与已绑定目录快照；目录漂移、未知/危险上游工具、认证/连接/响应 Schema 错误均拒绝并留痕。因 OP-003 的原生只读和响应大小 Gate FAIL，默认禁用 MCP，Gateway 必须有到 REST/Probe 的显式、安全、语义不变回退；不得连接测试控制面或将 MCP 失败伪装为目标系统事实。
7. 为 ToolDefinition、Binding、CatalogSnapshot 的受控种子/生命周期提供可重复入口，确保其不改写 OP-004 的不可变语义；所有对稳定工具的实际调用必须使用已有 append-only 执行/审计模型。
8. 添加单元、API 和实际 PostgreSQL 集成测试，覆盖工单状态机/幂等/冲突、两组织两用户隔离、角色/资源越权、稳定名及参数拒绝、风险工具拒绝、MCP allowlist/目录漂移/认证失败、REST/Probe 回退、健康范围、审计与执行快照完整性。
9. 更新 `TASKS.md`、`CURRENT_STATE.md`、必要运行说明和 `handoffs/OP-006.md`，记录实际验证、未实现边界以及 OP-003 MCP FAIL 结论不变。

## 实现与安全约束

- L0 是确定性权限、状态与副作用边界；Agent/Skill/RAG/MCP 返回均为不可信输入，不能改变授权、范围、风险级别或状态机。
- 只注册固定稳定名；Tool Gateway 根据服务端配置和 binding 降级，统一授权、Schema、稳定错误码、结果结构与 health scope。`check_target_connector_health` 只能返回 `CONNECTOR`，不得推出应用/运行时/任务健康。
- MCP 目录快照是观察而非授权。仅已审核 binding 可用；上游名称、endpoint、参数、目录哈希、响应字节数、超时和错误关联 ID 必须受限并进入审计。未知、SQL、创建、更新、保存、生成类 MCP 工具一律拒绝。
- 用户、组织、目标和资源范围从认证上下文进入 Repository/Gateway；调用参数不可扩大范围。错误与审计摘要必须脱敏，不保存 API Key、Cookie、密码、完整连接串或原始超长响应。
- 工单创建和转换使用数据库唯一键、事务及版本号；重复请求返回既有事实，冲突明确返回，不静默覆盖。所有业务状态改变均追加审计事件。
- Provider 回退必须可见、可审计且不伪造成功；MCP/REST/Probe 之间的结果 Schema、授权及 health scope 保持一致。Provider 本身故障与目标系统观测必须区分。

## 验收条件

1. 新迁移可从空库升级/降级/再次升级，`alembic check` 通过；实际 PostgreSQL 证明 User/角色/范围、工单、消息/时间线和审计与 OP-004 11 张表兼容，且不破坏其 append-only/目录快照约束。
2. API/服务测试证明服务端身份上下文强制组织、目标、资源和角色边界；两个组织/用户的跨范围工单、资源读取和工具调用均无数据泄漏。敏感内容不出现在结构化错误或审计摘要。
3. 工单状态机只接受合法角色/前置条件下的转换；幂等重复建单不重复写入，乐观并发冲突明确，所有创建/转换有 append-only AuditEvent。未有通过 Verification 的路径不得声明 RESOLVED/CLOSED。
4. 已注册稳定工具仅覆盖任务列出的只读语义；上游 MCP 名、REST URL、未知工具、SQL/创建/保存/更新/删除/Shell 和参数越权一律拒绝。固定 Skill 仍只引用稳定名，且其文件/哈希/冻结内容没有变化。
5. Gateway 对每次尝试保存已授权主体/范围、稳定名/Schema、binding/provider/upstream 快照、请求/结果安全摘要、状态、错误/关联 ID、耗时、幂等键、降级原因和关联 AuditEvent；执行历史不可被业务路径原地改写。
6. MCP Provider 默认关闭；其固定 allowlist、匹配 CatalogSnapshot、认证/连接/目录漂移/恶意或超限响应拒绝均有测试。MCP 失败时 Gateway 明确回退 REST/Probe，且同一稳定工具的 Schema、授权、错误和 health scope 不变；不得把 connector 健康表述为应用或运行时健康。
7. REST/Probe 在受控 fixture 下覆盖元数据、APPLICATION 与各 RUNTIME_COMPONENT 观测；Provider 故障与目标观测错误区分，输出长度/敏感字段受限制。
8. 后端锁检查、Ruff、format、`mypy src tests`、pytest 和实际 PostgreSQL 迁移/集成回归通过；前端 frozen install、format、lint、typecheck、production build 通过。`git diff --check`、密钥和大文件检查无异常；结果与未运行项如实写入交接。
